## Base rule

DO NOT rely on handwritten relative paths when JS can use OP_PATHS.
If a page/script needs navigation, prefer window.OP_PATHS.

Static include rule for nested HTML pages:

- From files inside:
  - html/app/
  - html/app/creators/
  - html/app/fans/
  - html/marketing/
  - html/marketing/faq/
  - html/marketing/legal/
  - html/thanks/

- shared assets / css / js / components use root-aware project paths through OP_PATHS when possible
- if hardcoded relatively inside nested html pages, many files currently use ../../
- BUT this is only safe when the actual folder depth matches
- so for future cleanup: prefer OP_PATHS over handwritten relative links

IMPORTANT:
- html/app/*.html and html/marketing/*.html are NOT at the same depth as:
  - html/app/creators/*.html
  - html/app/fans/*.html
  - html/marketing/faq/*.html
  - html/marketing/legal/*.html
- so one universal ../../ rule is NOT truly reliable for every html file
- central paths.js is the safe fix


## Shared assets paths

Preferred:
- use /js/paths.js
- resolve everything from window.OP_PATHS

Example shared files:
```html
<link rel="stylesheet" href="../../css/styles.css" />
<script src="../../js/paths.js"></script>
<script src="../../js/partials.js"></script>
